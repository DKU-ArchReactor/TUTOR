# 명령어 포맷 설명

기존 ASM 설명 항목에 선택 필드 `instruction_format`을 추가합니다. BE API 경로나 gRPC protobuf는 변경하지 않습니다. 기존 클라이언트는 이 필드를 무시할 수 있습니다.

포맷은 문자열 명령어를 추측해 결정하지 않고 32비트 기계어에서 추출합니다. 인식하지 못한 opcode나 잘못된 입력에는 포맷 정보를 제공하지 않습니다. 지원하지 않는 명령어의 실행 가능성을 보장하는 필드는 아닙니다.

## 응답

| 필드 | 의미 |
| --- | --- |
| `name` | R, I, S, B, U, J |
| `word` | 분석한 32비트 기계어 |
| `width_bits` | 32 |
| `description` | 포맷의 용도와 예외 |
| `fields` | 상위 비트부터 나열한 name, high, low, width, value, binary, role |
| `immediate` | 재조합·부호 확장한 즉치값. U형은 하위 12비트를 채운 값, 시프트는 5비트 이동 크기. 없으면 null |
| `basis` | `machine_code` |
| `note` | 필드 배치와 실제 레지스터 접근·실행값의 구분 |

S/B형에는 rd 필드를 만들지 않습니다. B/J형은 분산 비트와 생략된 최하위 0을 재조합합니다. I형 시프트의 funct7을 이동 크기로 오해하지 않습니다. ECALL의 고정 rs1/rd 필드를 일반 입력·결과 기록으로 설명하지 않습니다.

LUI/AUIPC, JAL/JALR, ECALL의 처리 순서·피연산자 역할 설명도 보완합니다. ECALL의 a7/a0 의미는 실행 환경의 호출 규약이며 명령어 자체의 rs1/rd 필드와 구분합니다.

## 검증 범위

현재 CORE decoder의 지원 명령어 46개를 대조했을 때 포맷·피연산자 역할·3단계 이상의 설명이 모두 존재합니다. 포맷별로 R 18, I 16, S 3, B 6, U 2, J 1개입니다. 이는 전체 RISC-V ISA를 지원한다는 의미는 아닙니다.

`python -m pytest -q`와 `python scripts/check-contract.py`를 실행합니다. 포맷 테스트는 비트 중복·누락 없이 원래 기계어를 복원하는지, 음수 변위·시프트·SYSTEM 구분을 확인합니다. 실제 BE/CORE를 사용한 시연 38건도 통과했습니다. 새 포맷의 운영 제공 여부는 이 변경을 배포한 후 확인해야 합니다.
