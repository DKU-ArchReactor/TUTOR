## 이번 점검에서 발견하고 보정한 정보

1. `puts("x++;");`의 문자열을 증가 연산으로 오인하던 C 구문 판정을 수정했습니다. `x = y++;`는 대입으로 설명합니다.
2. 표준 명령어 FENCE·EBREAK와 현재 CORE 실행 지원 범위를 구분합니다. 현재 CORE에서는 두 명령어가 실행 미지원임을 명시합니다.
3. CORE가 SRAI의 I형 필드 전체를 `1026`처럼 표시할 수 있습니다. 실제 이동 크기는 기계어 비트 24~20에서 얻은 2비트입니다. 정적 해설과 실제 실행 관찰 모두 유효 이동 크기를 사용하며 CORE 원본 결과는 변경하지 않습니다.
4. 새 모바일 AI 패널과 기존 팝업이 함께 존재하는 최신 FE에 맞춰 테스트가 보이는 입력을 선택하도록 수정했습니다. 모바일 튜터 검사는 최신 의도대로 ASM 줄 선택으로 모달을 엽니다. 제품 화면 코드는 변경하지 않았습니다.

## 검증 결과

- TUTOR: `python -X utf8 -m pytest -q`, 203개 통과. Starlette의 기존 의존성 경고 1개가 있습니다.
- gRPC proto·생성 코드·descriptor 일치 검사 통과.
- CORE 디코더가 인식하는 46종 각각의 기계어에서 생성한 ASM을 튜터가 해설하는지 확인했습니다. FENCE·EBREAK는 46종에 포함되지 않습니다. 이 검사는 ISA 전체 적합성 증명이 아닙니다.
- 실제 BE 컴파일·CORE 실행 및 배포 TUTOR 응답과 로컬 TUTOR를 대조했습니다. 19개 예제의 single/pipeline 38건 모두 통과했습니다. 원본 CORE 결과 불변성, 최종 레지스터·메모리, 매핑·완료 횟수·이벤트·CPI 집계를 검사했습니다.
- FE: 단위 검사 52개, 브라우저 검사 31개, TypeScript/Vite 빌드 통과.
- 개발 S3 화면과 로컬 FE에서 실제 BE를 연결해 덧셈 예제를 두 모드로 실행했습니다. 재생 추적·C/ASM 선택·개념 펼치기·실제 값·CPI/해저드, 밝은/어두운 테마·좁은 패널을 확인했습니다. JavaScript 실행 오류는 없었습니다.
- 전체 FE lint는 기존 오류 12개·경고 1개로 실패합니다. 이번 점검은 해당 ThemeContext·RegisterVisualizer 등 다른 개발 영역을 수정하지 않았습니다.
- 부하·응답 속도·동시 접속 용량을 측정한 결과는 아닙니다. 반복 작업 제거를 실제 배수 향상으로 표현하지 않습니다.

## 제출 전에 구분해야 할 배포 상태

### 개발 화면과 운영 화면이 다릅니다

TUTOR PR #5와 FE PR #29는 develop에 병합·배포됐습니다. 개발 화면에서는 새 튜터가 동작합니다.

- 개발: <http://archreactor-dev.s3-website-us-east-1.amazonaws.com/>
- 운영: <http://archreactor.s3-website-us-east-1.amazonaws.com/>

운영 main에는 `TutorPerformanceSummary.tsx`, `TutorTypography.css`, `tutorFocus.ts`가 없으며 develop에만 있는 커밋이 43개입니다. 반대로 main에는 새 AI 연동 변경이 있습니다. 최종 운영 반영은 두 브랜치의 변경을 함께 보존하는 PR로 검토해야 하며, 한쪽 파일을 통째로 덮어쓰면 안 됩니다. 이번 점검에서 main 병합·배포는 수행하지 않았습니다.

이번 C 구문·지원 범위·SRAI 보정은 로컬 작업 브랜치의 변경이므로 TUTOR PR 리뷰·병합·배포 후에 서비스에 반영됩니다. FE 제품 코드 수정은 없고 테스트만 조정했습니다.

### 직접 URL 접속 시 HTTP 상태

두 S3 호스트의 `/`는 200이지만 `/pipeline`, `/login`, `/simulator` 직접 요청은 404입니다. SPA HTML이 반환되어 확인한 화면은 동작하지만 HTTP 상태는 여전히 404입니다. 시연 진입은 루트 주소를 사용하세요. 정상 HTTP 200으로 고치려면 FE 호스팅의 SPA 경로 처리와 CloudFront 오류 응답 설정 등을 별도로 반영해야 합니다. 이번 점검은 AWS 설정을 변경하지 않았습니다.

## 제출 직전 변경 범위

이번에는 설명 정확성 보정과 재현 예제·회귀 검사에 집중했습니다. 서버 응답 중복 제거, 전체 실행 결과 복사 축소, 추가 가상화는 가능한 개선 후보지만 API 호환성·입력 불변성 검증이 필요한 별도 작업입니다. 제출 직전의 필수 수정으로 보지는 않습니다.

튜터는 완전한 C 파서·디버거나 최적화 효과 증명 도구가 아닙니다. 모든 C 변수 저장 위치, 특정 분기의 순수 손실 클록, 포워딩 절약 클록은 현재 근거만으로 확정하지 않습니다.
